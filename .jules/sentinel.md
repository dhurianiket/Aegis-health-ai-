## 2024-05-21 - Privilege Escalation in Firestore Rules
**Vulnerability:** Users could escalate privileges by setting `role: 'admin'` during user document creation or updates because `allow write: if isOwner(userId);` didn't restrict field-level modifications. Additionally, `/analytics/globalStats` allowed write access to any authenticated user (`request.auth != null`).
**Learning:** `allow write` encompasses `create`, `update`, and `delete`. When ownership grants write access to a document containing authorization claims (like `role`), field-level restrictions must be explicitly enforced on `update`, and payload validation must be performed on `create`. Furthermore, admin endpoints must use `isAdmin()` instead of basic authentication checks.
**Prevention:** Always split `write` into `create`, `update`, and `delete` when field-level restrictions are needed. Use `request.resource.data.diff(resource.data).affectedKeys().hasAny(['role'])` for updates, and check field presence and value for creates. Always use `isAdmin()` for admin-only endpoints.
